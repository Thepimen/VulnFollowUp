## Technical Glossary Table (35 Core Terms)

| # | English Term | Spanish Equivalent | Technical Definition (in English) | Context of Use in VulnFollowUp |
|---|---|---|---|---|
| 1 | **Attack Vector (AV)** | Vector de ataque | A CVSS base metric indicating the context by which vulnerability exploitation is possible (`Network`, `Adjacent`, `Local`, or `Physical`). | Parsed and validated in `cvss_vector` strings (e.g., `AV:N` for `VFU-0012` on the internet-facing payment API). |
| 2 | **Attack Complexity (AC)** | Complejidad del ataque | A CVSS metric describing the conditions beyond the attacker's control that must exist in order to exploit the vulnerability (`Low` or `High`). | Validated via regex in `database/schema/01_schema.sql` for both CVSS v3.1 and v4.0 payloads. |
| 3 | **Attack Requirements (AT)** | Requisitos de ataque | A metric introduced in CVSS v4.0 (`None` or `Present`) that captures prerequisite deployment or execution conditions of the vulnerable component. | Distinguishes CVSS v4.0 vectors (`CVSS:4.0/AV:.../AT:N/...`) from legacy v3.1 vectors in the backend validator. |
| 4 | **Audit Trail / Audit Log** | Registro de auditoría inmutable | A chronological, tamper-evident record of security-relevant events and state modifications showing who performed an action, when, and why. | Implemented in the `audit_logs` table to record every lifecycle state transition and administrative change. |
| 5 | **Associative Entity (Join Table)** | Tabla intermedia / asociativa (N:M) | A relational table that resolves a many-to-many (`N:M`) relationship between two entities by holding foreign keys referencing both primary keys. | The `vulnerability_assets` table links multiple `vulnerabilities` to multiple technological `assets`. |
| 6 | **Adaptive Password Hashing** | Hashing adaptativo de contraseñas | A one-way cryptographic function (such as BCrypt or Argon2id) designed with a configurable work factor and per-user salt to resist brute-force attacks. | Enforced in `users.password_hash` and `users.password_salt` (`$2b$12$...`), preventing plaintext storage. |
| 7 | **Base Score (CVSS)** | Puntuación base CVSS | A numerical score ranging from `0.0` to `10.0` that represents the intrinsic severity of a vulnerability, independent of time or environment. | Stored in `vulnerabilities.cvss_score` and `cvss_assessments.cvss_score` with a strict `0.0–10.0` `CHECK` constraint. |
| 8 | **Batch Ingestion** | Ingesta / Importación por lotes | The automated processing of a collection of data records in a single background job rather than individual manual entries. | Executed by `POST /api/vulnerabilities/import` using Java's `ExecutorService` thread pool. |
| 9 | **Composite Index** | Índice compuesto | A database index built on two or more columns to accelerate queries that filter and sort across multiple fields simultaneously. | `idx_vuln_status_severity_score` speeds up multi-filter paginated queries on `GET /api/vulnerabilities`. |
| 10 | **Contrast Ratio** | Ratio de contraste lumínico | The numerical measurement of relative luminance between foreground text and background surfaces, required to be at least `4.5:1` for WCAG 2.1 Level AA. | Verified across Dark and Light themes in `desktop-client/src/styles/tokens.css` (reaching `16.4:1` on primary text). |
| 11 | **Cryptographic Salt** | Sal criptográfica (*Salt*) | Random data generated uniquely for each user password before hashing, ensuring identical passwords produce distinct hashes and defeating rainbow tables. | Stored alongside the adaptive hash in the `users` table (`password_salt`) for all platform accounts. |
| 12 | **Data Transfer Object (DTO)** | Objeto de transferencia de datos | A serializable data contract used to carry structured fields between the backend API and client applications without exposing internal database entities. | Defined in `docs/api/openapi.yaml` and mirrored in `desktop-client/src/types/api.ts`. |
| 13 | **Digital Operational Resilience Act (DORA)** | Reglamento de Resiliencia Operativa Digital (DORA) | Regulation (EU) 2022/2554 establishing uniform cybersecurity and ICT third-party risk management requirements for European financial entities. | Forms the regulatory backbone of our SGE module (`ict_providers` and `GET /api/providers/{id}/report`). |
| 14 | **Entity-Relationship Diagram (ERD)** | Diagrama Entidad-Relación (E-R) | A structural diagram illustrating database tables, attributes, primary keys, and foreign-key cardinalities (`1:N`, `N:M`). | Maintained in Mermaid format at `database/er-diagram.md`, synchronized with `01_schema.sql`. |
| 15 | **Focus Ring (`:focus-visible`)** | Anillo de foco visible | A high-contrast visual outline rendered around the currently focused interactive element during keyboard navigation (`Tab` / `Shift+Tab`). | Styled globally in `desktop-client/src/styles/global.css` to meet WCAG 2.1 SC 2.4.7. |
| 16 | **Foreign Key Referential Integrity** | Integridad referencial por clave foránea | A relational database constraint guaranteeing that every foreign key value points to an existing, valid primary key row in the referenced table. | Protects links between `assets.provider_id` $\rightarrow$ `ict_providers.id` and `vulnerability_assets` $\rightarrow$ `assets`/`vulnerabilities`. |
| 17 | **Green Software Engineering** | Ingeniería de Software Verde / Sostenible | The discipline of designing software architectures that minimize CPU cycles, memory consumption, network bandwidth, and display energy usage. | Applied through mandatory server-side pagination, composite SQL indexes, Room caching, and OLED Dark Mode. |
| 18 | **ICT Third-Party Provider** | Proveedor tercero de servicios TIC | An external vendor supplying cloud infrastructure, payment gateways, or managed security services to a regulated organization. | Modeled in `ict_providers` (e.g., *HostingSur S.L.* providing the *API de pagos* asset). |
| 19 | **Idempotency** | Idempotencia | The property of an operation or script whereby executing it multiple times produces the same system state as executing it once. | Applied in `database/schema/01_schema.sql` (`DROP TABLE IF EXISTS ... CASCADE`) and `Upsert` DAOs in Android Room. |
| 20 | **JSON Web Token (JWT)** | Token Web JSON (RFC 7519) | A compact, digitally signed token containing claims (user identity, role, expiration) used for stateless HTTP authentication and authorization. | Issued by `POST /api/auth/login` and attached via `Authorization: Bearer <token>` in `apiClient.ts`. |
| 21 | **Mass Assignment Vulnerability** | Vulnerabilidad de asignación masiva | An API flaw where an attacker injects unpermitted JSON properties into a request payload to overwrite sensitive server-side fields. | Prevented in `docs/api/openapi.yaml` by enforcing `additionalProperties: false` on every request schema. |
| 22 | **Mutual Exclusion (Mutex / Lock)** | Exclusión mutua / Bloqueo de sincronización | A concurrency mechanism (`ReentrantLock` or `synchronized`) that prevents multiple threads from modifying shared state simultaneously. | Used in the Java backend's batch vulnerability processor to prevent counter corruption during parallel imports. |
| 23 | **Offline-First Persistence** | Persistencia con prioridad sin conexión (*Offline-First*) | A mobile client architecture that reads from and writes to a local SQLite database (`Room`) first, synchronizing with the remote API when connectivity is available. | Implemented in `android-app/` so field analysts can inspect CVEs and DORA alerts without network coverage. |
| 24 | **OS Process Spawning (`ProcessBuilder`)** | Creación de procesos del sistema operativo | The controlled execution of an external operating system command or script as a child process from within the Java Virtual Machine. | Used by `GET /api/reports/export` to generate executive CSV and HTML vulnerability reports safely without shell injection. |
| 25 | **Parameterized Query (`PreparedStatement`)** | Consulta parametrizada / Sentencia preparada | A database execution technique that separates SQL code from user-supplied parameters, completely neutralizing SQL Injection (`CWE-89`). | Enforced across all JPA/JDBC data access methods in `backend/`. |
| 26 | **Qualitative Severity Rating** | Escala cualitativa de severidad | The standardized categorical mapping of numeric CVSS scores into five discrete levels: `NONE`, `LOW`, `MEDIUM`, `HIGH`, and `CRITICAL`. | Validated against `cvss_score` via `chk_vuln_cvss_score_severity_coherence` in PostgreSQL. |
| 27 | **Race Condition** | Condición de carrera | A concurrency defect that occurs when two or more threads access shared mutable data concurrently and the final outcome depends on thread scheduling order. | Tested deterministically in `backend/` using JUnit 5 and `CountDownLatch` to prove thread safety. |
| 28 | **Remediation Lifecycle State Machine** | Máquina de estados del ciclo de remediación | A finite set of workflow states and transition rules governing how a vulnerability progresses from discovery to closure. | Enforces `ABIERTA` $\rightarrow$ `PENDIENTE DE REMEDIACIÓN` $\rightarrow$ `RESUELTA` $\rightarrow$ `CERRADA`. |
| 29 | **Remediation SLA (Service Level Agreement)** | Acuerdo de Nivel de Servicio (SLA) de remediación | The maximum permitted timeframe within which a confirmed vulnerability must be patched or mitigated based on its severity and asset criticality. | Tracked via `target_remediation_date` in `vulnerabilities` and escalated when overdue. |
| 30 | **Role-Based Access Control (RBAC)** | Control de acceso basado en roles | An authorization model that restricts system actions based on the operator's assigned organizational role rather than individual identity. | Enforces permissions across `ADMIN` (full control), `ANALYST` (triage & remediation), and `VIEWER` (read-only audit). |
| 31 | **Server-Side Pagination** | Paginación en el servidor | Splitting large query result sets into bounded subsets (`LIMIT` / `OFFSET` via `page` and `size`) on the database server before transmitting over HTTP. | Mandatory on `GET /api/vulnerabilities` and `GET /api/assets` to reduce network payload size by >99%. |
| 32 | **Supply-Chain Exposure** | Exposición de riesgo en la cadena de suministro | The security risk inherited by an organization when a critical third-party ICT vendor suffers an unpatched vulnerability on a hosted asset. | Exemplified when *HostingSur S.L.* is flagged `AT_RISK` due to `VFU-0012` affecting *API de pagos*. |
| 33 | **Third Normal Form (3NF)** | Tercera Forma Normal (3FN) | A database normalization standard where every non-key attribute is fully functionally dependent only on the primary key, eliminating transitive dependencies and data redundancy. | Applied across all 8 tables in `database/schema/01_schema.sql`. |
| 34 | **Thread Pool (`ExecutorService`)** | Pool de hilos de ejecución | A managed collection of reusable worker threads that execute asynchronous tasks from a bounded queue without the overhead of spawning unbounded OS threads. | Powers concurrent CVE batch validation and ingestion in the Java backend (`PSP` module). |
| 35 | **Transactional Rollback (ACID Atomicity)** | Reversión transaccional (*Rollback* ACID) | The database mechanism that undoes all statements executed within a transaction if any single operation fails, preserving data consistency. | Proven during the AD defense using `data/vulnerabilities_invalid_rollback_test.json`. |
